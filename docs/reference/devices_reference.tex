\section*{How to read this document}

A \emph{device} is one processing tool in a layer's chain. \textbf{Transforms} compute
(they head chains and produce a result bundle); \textbf{filters} select from a computed
result (list indexes and masks --- scrubbing a filter knob redraws without recomputing).
Chains are always transforms-then-filters; interleaving is rejected at construction.

Each tool has a display name and a device id. The device browser lists tools by scientific
family and, like the chain strip, shows a tool's display name with its id in grey; this reference
names a tool the same way: \tool{WTMM 2D}{wtmm2d}. Saved chains, rack files, layer
names, cache keys and provenance record the device id. Each tool declares the data it consumes
and produces, and one rule derived from those declarations says whether a step applies
(\S\ref{sec:contracts}). The tables of families, contracts, applicability and output rows are
written by \texttt{make\_tables.py} from the tools' own declarations, as the kernel figures are
drawn from the kernel code.

Conventions that hold everywhere:
\begin{itemize}\itemsep2pt
  \item \textbf{Scales are stored in pixels}, converted only for display.
  \item \textbf{The shown level is view state}: the Transport sets it for each layer
        (\S\ref{sec:transport}), and no chain step holds it.
  \item \textbf{The wavelet family belongs to the method}: each tool's menu lists only the
        kernel class its method admits, under the method's own names.
  \item \textbf{Inert knobs}: a parameter that binds only under one choice of another
        parameter (e.g.\ $q$ only for q-family wavelets) is ignored otherwise; where the device
        declares it, the knob is \emph{greyed out} in the device box while it does not apply
        (its value is kept).
  \item \textbf{View-only knobs} (marked \emph{view} in the tables) choose what is shown from
        a result that is already computed and cached --- Show, Component, Group, Orientation,
        Show PC. Switching one redraws at once; it never recomputes.
  \item \textbf{Orientations are $(\text{angle},\text{frame})$}, the frame being the pixel
        grid or grid, true or magnetic north (\S\ref{sec:arrows}, Gradient arrows and anisotropy).
  \item \textbf{No-support masking}: pixels with no honest signal support (nodata flats,
        FFT dust) are NaN in every exponent map.
  \item Each table lists: parameter (UI label), default, hard range, and meaning. Soft
        ranges (knob-drag limits) are narrower than hard ranges.
  \item \textbf{A step that does not apply} (a V-chain filter after an analysis without
        V-chains) stays in its chain with its knobs, drawn inactive with the reason, and the
        engine skips it. Bypassing a step is the user's own act.
\end{itemize}

\subsection*{Wavelet normalization: $L^1$}
Every wavelet in the app is normalized in the $L^1$ (pure-dilation) convention,
$\psi_a(x)=a^{-d}\,\psi(x/a)$ in $d=2$ dimensions, so that at a H\"older singularity the
transform scales as $|T_\psi[f](x,a)|\sim a^{h(x)}$ with no offset. The $L^2$ convention
($a^{-d/2}$, unit energy $\int\psi^2=1$ --- e.g.\ the normalization constants $A$ and
$A_q$ of Borges et al.\ 2004, whose transform carries $a^{-1/2}$) shifts every exponent by
$d/2$. Turiel's microcanonical formalism uses the same $L^1$ dilation
$\Psi_r(x)=r^{-d}\Psi(x/r)$ (Turiel et al.\ 2008, eqs.~6--8). Borges et al.'s own WTMM
example agrees in practice: their eq.~41 reads $T\sim a^{\alpha}$ (their fig.~5 recovers
$\alpha=0.5$), which holds for $L^1$ scaling, not for the $a^{-1/2}$ of their eq.~10.
\begin{itemize}\itemsep2pt
  \item \textbf{\dev{wtmm2d} normalizes in the Fourier domain.} Each filter is built as
        $\hat\psi(a\mathbf{k})$ from a smoothing function with $\hat\theta(0)=1$
        (unit mass at every scale), times the derivative factor $i\,a\mathbf{k}$: scale
        enters only through $a\mathbf{k}$, which \emph{is} the $L^1$ dilation.
  \item \textbf{The H\"older tools normalize in real space} by default, on the pixel grid:
        positive kernels (\dev{holder\_measure}) to unit discrete mass; Mexican hats
        (\dev{holder\_multiaffine}) to exact zero mean, then unit $L^1$ norm
        ($\sum|\psi_r|=1$), at every scale. With \emph{Wavelet space} set to Fourier
        (\S\ref{sec:micro}) they are built as $\hat\psi(r\mathbf{k})$ instead, like
        \dev{wtmm2d}'s filters.
  \item A constant prefactor that does not depend on the scale (such as $A$ or $A_q$)
        cannot change any exponent --- it only shifts $\log|T|$ --- and the app's own
        normalization replaces it anyway. Only the \emph{scale dependence} of the
        normalization matters.
  \item \textbf{Validated on a synthetic cusp} $|x-x_0|^h$: both routes recover the slope $h$
        (tests pin it; an $L^2$ slip would read $h+1$ in 2-D). The smallest scales are biased
        by the discretization of both kernel and signal: at a sampled cusp the slope settles
        above $\sigma\approx5$\,px (\dev{wtmm2d}) and $r\approx10$\,px (the Mexican hats), later
        for sharp-cutoff kernels ($q_T<1$).
  \item \textbf{Two different $q$'s.} $q_T$ (the knob \emph{Tsallis q} of the H\"older tools)
        is the Tsallis/Borges shape parameter of a kernel; $q$ in $Z(q,a)$, $\tau(q)$ and
        $D(h)$ is the moment order of the partition functions. They are unrelated.
\end{itemize}

\section{The workspace: datasets, layers, ROIs, derivatives}\label{sec:workspace}

\textbf{Datasets.} Every opened file is a \emph{dataset}: one row in the layer tree, and
that row \emph{is} its raw layer (its H hides the raster; right-click $\to$ Remove dataset
takes the dataset and everything on it). A plain image (PNG/JPEG) opens as one luminance band;
a multiband GeoTIFF / netCDF / HDF stack opens as $(n_y,n_x,n_c)$.

\textbf{Children.} A tool dropped on a dataset never replaces the data: it spawns a
\emph{child} layer holding that tool, nested under the dataset. A child re-runs its chain on
its parent's data whenever that changes. Right-click on a result row: \emph{Delete layer}
(its children move up to its parent) or \emph{Delete layer and children}; shift-click or Cmd-click (Ctrl on Windows)
selects several rows for one Delete. \textbf{H never cascades}: each row hides only its own
drawing (the dataset's H hides the dataset raster, not the results over it).

\textbf{ROIs.} A saved region of interest is stored in whole \emph{file} pixels and shown as
a row \texttt{dataset @A} under its dataset. Selecting the ROI row makes it the region the
next tool runs on; results (\texttt{tool @A}) nest under it. The ROI row's H hides only its
outline. An ROI cannot be deleted while results use it (delete them first). Analyzers read
their own declared margin around the ROI; decompositions (\dev{pca},
\dev{tucker\_HOOI\_HOSVD}, \dev{ssa2d}) analyse the ROI itself (margin $0$: a margin would mix
outside data into the statistic).

\textbf{Output rows.} A result whose tool produces several things carries a collapsed
\emph{Outputs} group under its row: one row per output, each with its own H
(the \hyperref[tab:outputs]{output-rows table} below lists every tool's rows). Raster outputs share the canvas one at a time: showing one
hides the others, and hiding the one shown puts back what the tool's \texttt{show} shows by
default (the data, or an MFA tool's $h$ map). They follow the tool's
\texttt{show} knob, and switching between them re-uses what was computed. The \emph{edges} row
hides the maxima dots and gradient arrows (and the H-lines in the Vector and Geo views); the
result keeps its maxima, so filters, the spectrum and the anisotropy window still read them.
The layer's own H hides everything the result draws. An output that needs its own computation
(the \dev{mz\_edges} reconstruction, an MFA tool's band, one level of a per-scale output,
\S\ref{sec:perscale}) runs the first time it is shown, with progress and Stop,
and stays cached; Freeze (the row's F) keeps it.

\input{tables/outputs}

\textbf{Progress} is live: every compute reports one increasing fraction from inside its own
loops.

\textbf{The right panel} shows what applies to the selected row: the colours, widths and
arrows of the WTMM overlays appear with a result that has maxima or chains,
\emph{Reconstruct\ldots} with an $h$ map, colormap, stretch and hillshade with a single-band
display (a multiband display uses the Composite section), and the view-specific sections in
the Vector and Geo views.

\subsection*{Derivative datasets (Fork)}

result shows and from then on is an \emph{original raw dataset}: nothing links it back, and a
tool dropped on it spawns a child that analyses the derivative's own pixels.

\subsection*{The Components window}
Right panel $\to$ Decomposition $\to$ \emph{Components\ldots}, on a \dev{ssa2d} or
\dev{tucker\_HOOI\_HOSVD} result:
\begin{itemize}\itemsep2pt
  \item \textbf{thumbnails} --- the eigenarrays (\dev{ssa2d}: the $L_r\times L_c$ window
        patterns) or the component images, each labelled with its share;
  \item \textbf{the shares} on a log scale (group members in amber) --- a slowly decaying
        floor is noise;
  \item \textbf{the w-correlation matrix} (\dev{ssa2d}; black $0$ to white $1$) ---
        separable components are nearly w-orthogonal, so groups show as blocks on the diagonal;
        hovering reads $w(C_i,C_j)$.
\end{itemize}
Clicking thumbnails picks the \textbf{group}: click one, Cmd-click (Ctrl) to add or remove,
shift-click for a range, \emph{All} for every one. The pick is written into the tool's Group
knob (and the window follows the knob), so the canvas redraws from the cache.

\subsection*{Multidimensional rasters}
\textbf{Import.} Opening a multi-grid container (netCDF, HDF5, HDF4) shows an import dialog:
the image grids grouped by sensor and resolution with a checkbox per band, and the remaining
grids (geolocation lattices, calibration tables, supplements) in a collapsed \emph{Ancillary
grids} group, each importable on its own. Each ticked group becomes one multiband dataset
$(n_y,n_x,n_c)$. Grids of different resolution are separate datasets: ASTER's VNIR (15\,m),
SWIR (30\,m) and TIR (90\,m) arrive as three. HDF4 grids are named by their swath group
(\texttt{VNIR\_Band3N/ImageData}), since ASTER names every band's array
\texttt{ImageData}. A dataset is its file together with its band list, so two groups
imported from one file are two datasets, each with its own row, cache and saved state.

\textbf{Band rows.} A multiband dataset lists its bands under a collapsed \emph{Bands ($n$)}
row. Each band row is a child layer whose chain starts with \dev{band\_select}: selecting it
shows that band, and a tool dropped on it runs on that band alone. \emph{Remove band from
project} (right-click, or Delete) takes the band out of the dataset together with its row
and any results under it; the file is untouched, and the last band stays. The removal
changes the dataset's identity, so a result computed on the fuller stack is recomputed.

\textbf{Composite.} A multiband dataset draws as an RGB composite. The \emph{Composite}
section of the right panel lists the bands with a channel (R, G, B or none; each channel
takes one band) and Solo / Mute buttons: mute drops a band's channel; one solo shows that
band alone in grey; several solos keep each in its channel. Its \emph{Stretch} applies one
type to all channels, each computed from its own band's values:

\begin{longtable}{L M}
\toprule Stretch & Mapping to $[0,1]$ \\ \midrule
linear (min--max) & minimum to maximum (normalisation) \\
percent clip & the $p$-th to $(100-p)$-th percentiles, clipped ($p=2$ is ENVI's linear 2\,\%) \\
std-dev & mean $\pm k\sigma$, clipped \\
log & $\log(1+v-\min v)$, then minimum to maximum \\
histogram equalize & each value's rank among the finite values \\
bipolar & $-m$ to $+m$, $m$ the $(100-p)$-th percentile of $|v|$: zero maps to mid-scale,
          for signed data (principal components, residuals) \\
\bottomrule
\end{longtable}

The single-band Display stretch offers the same six types. Stretches are display only;
analysis reads the band values themselves.

\textbf{What a field stage shows.} A chain that ends on a field stage shows the field it
produces: \dev{noise} alone shows the noised field (a stack through the composite), a band row
its band, a bus its stack. Bypassing the stage shows the raw data again, and \emph{Fork
derivative dataset\ldots} takes the produced field, one band per checkbox.

\subsection*{Buses: routing bands into one stack}\label{sec:buses}
Multi-band tools (\dev{pca}, \dev{tucker\_HOOI\_HOSVD}) take a stack $(n_y,n_x,n)$. A
\textbf{bus} assembles one from the bands of any datasets on the same grid. It heads a child
layer's rack (\dev{bus}), and a tool dropped after it analyses the bus's stack. Right-click a
dataset row $\to$ \emph{Route bands to a new bus\ldots}:
\begin{itemize}\itemsep2pt
  \item \textbf{Sends} are picked per band from every loaded dataset; a dataset on another
        grid is listed greyed out with the reason. A send references the band in its file
        (the file path and the band's grid id or index); the bus reads the band when it
        computes, over the window it needs.
  \item \textbf{Channel order} (drag to reorder) is the band axis the tool receives.
        \dev{pca} and \dev{tucker\_HOOI\_HOSVD} give the same decomposition in any order, with
        the per-band loadings in that order; band math and the composite's default channels
        depend on it.
  \item \textbf{Same grid}: every send has the bus's shape, pixel step, georeference anchor and
        CRS. Combining grids of different resolution requires resampling, which the bus does
        not do.
  \item \textbf{Windows}: on an ROI the bus reads each band over the ROI's processing window,
        reflect-padded at the file edges exactly as the dataset itself is.
  \item \textbf{Returns}: the results of the tool after the bus are ordinary result rows;
        forking one makes it a dataset of its own.
  \item \emph{Edit bus sends\ldots} (right-click the bus row) re-opens the routing; a routing
        already computed is answered from the cache.
\end{itemize}

\textbf{Live band stacks.} Select two or more layers (shift- or Cmd-click), right-click
$\to$ \emph{Build band stack from $N$ selected layers}: a bus whose sends are the rasters those
layers show (a reconstruction, a noised band, an $h$ map), referenced live. Each send carries
a fingerprint of its layer's chain; editing a referenced layer changes the fingerprint, and
the stack recomputes when next shown. Referenced layers are computed first when needed, and a
deleted one is reported by name. The layers share the stack's grid (an ROI result has its own
grid and is refused). Layer sends and file sends mix in one bus.

\subsection*{The shown level: the Transport}\label{sec:transport}
The Transport under the canvas (a slider, play, and a reading of the scale in pixels and in the
dataset's units) sets the level the active layer shows. The level is view state: each layer
keeps its own, saved with the project, and scrubbing it leaves the chain as it is. After the
last Transform that applies, when the analysis holds an extrema stack of more than one level,
the engine takes the shown level out of the stack and then runs the filters, so a filter knob
redraws one level. The V-chains stay whole: the 3-D scale-space view lifts them through every
scale, and the anisotropy window reads every level. The Transport works on every multi-scale
layer, the \emph{WTMM + H\"older} rack's included, and the vector (3-D) view draws a layer's
extrema at the level that layer shows. Bands stay rows of their dataset; the Transport ranges
over scales only.

Each inspector window has a Transport of its own. With its \emph{M} button on (the default) it
follows the main Transport; with it off the inspector holds a level of its own. Two views of
one layer at two levels resolve the same cached analysis, each at its level.

\textbf{\dev{scale\_select} is superseded.} It stays registered, in the browser's Dev group. Of
the built-in racks only \emph{WTMM standard}, the default chain, holds it. Opening a project
whose chain holds it sets the layer's level from its \texttt{scale\_idx} once; the step stays
in the chain, drawn inactive with the reason ``the scale is set by the Transport''.

\subsection*{Per-scale outputs and levels marked for figures}\label{sec:perscale}
The multi-scale analyzers carry one raster row per scale-space output, off by default
(\emph{per level} in the \hyperref[tab:outputs]{output-rows table}):
\begin{itemize}\itemsep2pt
  \item \tool{WTMM 2D}{wtmm2d} and \tool{WTMM 2D, ROI}{wtmm2d\_roi}: \texttt{modulus} and
        \texttt{argument}, the wavelet transform's modulus and argument at one scale;
  \item \tool{Mallat--Zhong edges}{mz\_edges}: \texttt{modulus} and \texttt{argument} at one
        dyadic level;
  \item \tool{CDF edges}{cdf\_edges}: \texttt{re\_scale} and \texttt{im\_scale}, the Re and Im
        snapshots at $\sigma_k$;
  \item \tool{Perona--Malik edges}{pm\_edges}: \texttt{filtered\_scale}, the diffused raster at
        $\sigma_k$.
\end{itemize}
A row that is on shows the level the Transport is on and reads that level's scale in pixels; a
row that is off computes nothing, and the levels it computed while on stay cached until the
bounds below evict them. Turning a row on is a choice for that layer alone.
Each level is its own cache entry. WTMM~2D and the Mallat--Zhong edges compute the one level
asked for (one FFT pair, one filter cascade); the CDF and Perona--Malik evolutions are
sequential, so the first request runs the evolution once and keeps every snapshot as one
entry. Each output runs the tool's own per-scale routine with the analysis's knobs (WTMM~2D:
its dither and $a^{\eta}$ lift as the analysis applied them); with the \texttt{nms} detector the
maxima of WTMM~2D's level-$k$ modulus are the stored level-$k$ extrema. A
\tool{WTMM 2D, ROI}{wtmm2d\_roi} layer made by \emph{Save + run WTMM} draws its rows on the
ROI's own grid; a result run on an ROI row (\texttt{tool @A}) computes no lazy outputs.

\textbf{Marking a level for figures.} Right-click a per-level row $\to$ \emph{Mark level $n$ for
figures} ($n$ counts from 1 at the finest level; \emph{Unmark} on a marked level). The row
reads \emph{marked}, and the marks are saved with the layer. A marked level is pinned in the
cache while its row is on, so eviction passes it by; unmarking it, or turning the row off,
releases it. \emph{File $\to$ Export Derived Raster (.npz)\ldots} writes the level on show; its
provenance names the output (\texttt{<device id>/<output>}), the level and the marked levels
(counted from 0), and the status line lists the marked levels.

\textbf{Memory.} The cache holds at most 64 unpinned entries. The raster outputs also share a
byte budget, 2\,GB by default, set by \texttt{output\_cache\_bytes} in the settings file
(\S\ref{sec:racks} gives its folder); a $4096^2$ float32 level is about 67\,MB. Past the budget
the least recently used unpinned output levels go first. Fields, stacks and analysis results
stay under the entry bound alone.

\section{Tool families and data contracts}\label{sec:contracts}

\textbf{Families.} The device browser lists tools by scientific family (the
\hyperref[tab:families]{families table}), and a tool in several families is listed under
each. The \emph{Dev} group, collapsed, holds the parameter-schema stubs, the superseded tools
(kept registered so that saved projects open and resolve) and the steps the shell places
itself. A tool that declares no family is listed by its id under \emph{Other}. The last
group, \emph{Racks}, lists the built-in racks and the user's own (\S\ref{sec:racks}).

\input{tables/families}

\textbf{Contracts.} Devices pass named kinds of data, the
\hyperref[tab:contracts]{contracts}, and every tool declares the ones it consumes and the ones
it produces (the \hyperref[tab:declarations]{declarations table}). In a declaration ``or''
separates alternatives (Tucker takes a Field or a Stack) and ``+'' joins contracts needed
together. \emph{What it received} passes the step's input through: \dev{noise} keeps a field a
field and a stack a stack, and \dev{chain\_topology} adds the topology to the analysis it
reads. A declaration marked $\dagger$ depends on the parameters; the table gives it at the
defaults, then each choice that changes it. A \dev{bus} produces a Field from one send and a
Stack from several.

Every tool carries its origin: who wrote its code, under which licence, and the paper behind the
method. A tool marked derived runs code ported from another program, named in \texttt{NOTICE};
the browser shows the same lines in the tool's tooltip.

\input{tables/origins}

\textbf{The rule.} Before the first step the layer's input is available: a Field for a
single-band raster, a Stack for an $(n_y,n_x,n_c)$ raster with $n_c>1$, Points for a point
set. A band row's \dev{band\_select} turns its dataset's Stack into a Field. Then, step by
step:
\begin{itemize}\itemsep2pt
  \item a Transform applies when one of its alternatives is available, and its products then
        replace the available set;
  \item a Filter applies when one of its alternatives is available, and leaves the set as it
        is;
  \item a step that does not apply leaves the set as it is.
\end{itemize}
The engine skips a step that does not apply, so the step is absent from the dependency set and
from the cache keys, and the last Transform that applies is the analysis the layer's output
rows come from. The chain strip draws the step inactive with the reason, which names the
missing contract, the tools that produce it and the current analysis: ``needs V-chains: WTMM 2D
and WTMM 2D, ROI produce it; the current analysis (CDF edges) does not''. The step keeps its
place and its knobs, and it runs again as soon as its input is there. A tool that declares no
consumes always applies, and a Transform that declares no products counts as producing every
contract, so a tool from outside this build keeps working.

\textbf{Where the rule is used.}
\begin{itemize}\itemsep2pt
  \item \textbf{Browser.} A tool that cannot apply as the next step on the active layer is
        greyed, with the reason in its tooltip. A greyed row still drags, and the step lands
        drawn inactive. A tool that reads a Field or a Stack stays available on an analysed
        layer, because dropping it there forks a sibling.
  \item \textbf{Chain strip.} Each step that does not apply is drawn inactive with its reason.
  \item \textbf{Fork.} A primary analyzer reads a Field or a Stack and produces neither: the
        edge, regularity, skeleton and decomposition tools. Dropped onto a layer headed by a
        different one, it forks a sibling layer; dropped onto a dataset row, it spawns a child.
        The sibling begins with the parent's leading routing steps (a band row's
        \dev{band\_select}, a \dev{bus} with its sends), so it analyses the same field.
  \item \textbf{Shipping.} A filter on the parent moves to the sibling, with its knobs, when it
        applies after the sibling's analysis and does not apply after the parent's.
  \item \textbf{Racks.} A rack is greyed where its first step cannot apply, and the rack editor
        runs the rule along the rack (\S\ref{sec:racks}).
\end{itemize}

\textbf{Which tool applies after which.} The \hyperref[tab:applicability]{applicability
table} is the rule run for every selection tool after every analysis. The extrema filters
apply after each tool that produces an extrema stack. The V-chain filters,
\tool{Chain topology}{chain\_topology} and \dev{hline\_modulus} in mode
\texttt{sup\_all\_scales} apply after the WTMM tools, which produce V-chains.
\tool{Min V-chains per H-line}{min\_vchains} applies after Chain topology, and
\tool{H-line H\"older}{hline\_holder} after the Mallat--Zhong edges of the authors' algorithm,
whose analysis stamps a per-point $\alpha$. A derivative dataset's frozen vectors
(\dev{derived\_vectors}) carry an extrema stack and V-chains, the contracts of a WTMM~2D
analysis, so the same tools apply after them.

\section{Racks}\label{sec:racks}
A \emph{rack} is a named chain to drop onto a layer. The browser's \emph{Racks} group lists the
built-in racks and the user's own; double-clicking one opens it in the rack editor.

\section{Primary analyzers}
Each primary analyzer is its own representation of the field: it reads a single-band field
(or a band stack) and produces an analysis. Dropping a different primary analyzer onto an
analysed layer forks a sibling layer, and the filters that apply only after the new analyzer
move with it (\S\ref{sec:contracts}).

\subsection{\tool{WTMM 2D}{wtmm2d} --- canonical WTMM (Arn\'eodo)}
The canonical multifractal machinery: a continuous wavelet transform over a geometric
scale grid, modulus \emph{maxima} detected per scale (along-gradient non-maxima suppression,
or xsmurf's \texttt{follow}), maxima chained
across scales into maxima lines, feeding partition functions
$\to\tau(q)\to$ Legendre $D(h)$. The maxima are dense by design --- they are the
statistical support, not a lineament map (use the filters, or the other analyzers, for
sparse features). Legendre spectra are concave hulls by construction; the microcanonical
tools (\S\ref{sec:micro}) measure $D(h)$ directly --- together they diagnose
non-concavity.

\begin{figure}[h]
\centering\includegraphics[width=\textwidth]{wtmm_pair.pdf}
\caption{\dev{wtmm2d}: the smoothing function $\theta$ and the analyzing wavelet
$\psi=\partial\theta$ on the same axes (sections through the 2-D kernels, $x$ in units of
the smoothing $\sigma$). The wavelet is the derivative of the smoothing function, so the
modulus maxima of $\psi$ are the edges of $\theta$-smoothed data.}
\end{figure}

\paragraph{The smoothing function.} \texttt{wavelet} names $\theta$; the analyzing wavelet
is always its gradient. Four smoothers share one scale convention (a nominal scale $a$ is a
real-space $\sigma=a/(\pi\sqrt2)$) and one Fourier construction, every derivative filter being
$(\mathrm{i}s_x)^p(\mathrm{i}s_y)^q\,\hat\theta(s)$ with $s=a\,k$: the \emph{Gaussian}
($\psi=g_1$) and the \emph{Mexican hat} $|k|^2\hat G$ ($\psi=g_3$), the two xsmurf kernels; the
\emph{fractional B-spline} of degree $\alpha$, taken in its isotropic polyharmonic form (Van De
Ville, Blu \& Unser 2005: $\hat\theta=(V(\omega)/\|\omega\|^2)^{(\alpha+1)/2}$ with the
localization $V=4\sin^2\tfrac{\omega_1}{2}+4\sin^2\tfrac{\omega_2}{2}-\tfrac83\sin^2\tfrac{\omega_1}{2}\sin^2\tfrac{\omega_2}{2}$,
isotropic to fourth order, where a separable spline would bias the gradient directions the
WTMM reads), its knot spacing chosen so its width matches the Gaussian's at the same $a$; and
the \emph{q-Gaussian} $e_q(-\rho^2/2\sigma^2)$ through its radial q-Fourier transform
(Borges et al.), the same kernel the microcanonical tools offer, $q\to1$ being the Gaussian
exactly; the \emph{q-Mexican hat}, $-\Delta$ of that q-Gaussian smoother (its analyser the
q-$g_3$, in closed form by the chain rule on $e_q$; Borges's own index is $q_B=2-1/q$), which
needs $q>2/3$ for a continuous analyser at the support's edge; and a \emph{q-Meyer}
smoother, the generalization Borges et al.\ leave open in their closing remark: Meyer's
radial scaling-function taper with $\cos(\tfrac{\pi}{2}\nu)$ replaced by $\cos_q(x_0\nu)$,
$x_0$ the q-cosine's first zero, so it is bandlimited and isotropic, its dilation fixed at
$q=1$ so that its band peak is the Gaussian's. In two dimensions the fractional $\psi$ is continuous for $\alpha>2$ (the knob allows
$\alpha\ge1$ for exploration, default 3) and the q-Gaussian has finite mass for $q<2$; its
variance diverges from $q=5/3$, so its scale is matched by the parameter $\sigma$, never by the
variance. The wavelet scale bar and the $a_{\min}$ reading draw each smoother's own section and
locate its band peak $\lambda^*$ numerically ($\lambda^*$ of the fractional spline at $\alpha=3$
is the Gaussian's within 3\,\%; the q-Gaussian's tails lengthen it above $q=1$ and shorten it
below). The two new smoothers run on the device (mlx) on Apple Silicon and on FFTW3 elsewhere,
exactly as the pair does; the three engines agree to float32 tolerance.

\subsection*{Lineal path}\label{sec:lineal}
\tool{Lineal path}{lineal\_path} (family Microstructure) thresholds the field into two phases
(\texttt{threshold}: phase 1 lies above it) and computes the lineal-path function $L(r)$, the
probability that a segment of $r$ pixels dropped along a row or a column lies entirely in phase 1
(\texttt{direction}: horizontal, vertical or the mean of both), for $r = 0 \ldots$ \texttt{r\_max};
$L(0)$ is the phase fraction and $L$ never increases. It produces a Curve, the pair $(r, L(r))$,
counted exactly from the phase-1 run lengths without periodic wrap.

\subsection*{Gradient arrows and anisotropy}\label{sec:arrows}
The argument $\mathcal{A}=\arg T_\psi$ of each maximum points uphill in the pixel frame:
$0^\circ$ toward increasing column, $+90^\circ$ toward increasing row (clockwise on screen).
\textbf{Gradient arrows} (Display section: off / on WTMMM / on all maxima) draw one arrow per
point at the current scale, half the scale long (at most 12\,px) and scaled by modulus. The
WTMMM are the maxima of the modulus along each maxima line (xsmurf's \texttt{ssm}).

\textbf{Anisotropy} (Spectrum section) plots the WTMMM statistics of Arn\'eodo, Decoster and
Roux (2000, \S6): the density $P_a(\mathcal{A})$ at several scales, flat for an isotropic
field; the WTMMM of one scale in the gradient plane $(T_{\psi_1},T_{\psi_2})$, round for an
isotropic field; and the density of $\log_2\mathcal{M}$ in four axial sectors of
$\mathcal{A}$ (mod $180^\circ$, centred on $0^\circ$, $45^\circ$, $90^\circ$, $135^\circ$),
whose shapes coincide when $\mathcal{M}$ and $\mathcal{A}$ are independent.

\textbf{Frames.} Angles are shown in the pixel frame or, for a georeferenced dataset, as
azimuths: from grid north for a projected CRS (from the directions its axes run), from true
north by adding the meridian convergence at each point, and from true north directly on a
longitude/latitude grid. A dataset without a CRS (a sensor swath, a pixel grid) offers the
pixel frame only.

\subsection{\tool{Mallat--Zhong edges}{mz\_edges} --- dyadic multiscale edges}
Mallat and Zhong's multiscale edges (``Characterization of Signals from Multiscale Edges'', 1992),
computed with the authors' own algorithm: LastWave's \texttt{dwtrans2d} package (Bacry, Mallat,
Zhong, Hwang et al.), ported to numba and matching its C bit for bit on square fields. The dyadic
wavelet transform is computed \`a trous by direct FIR convolution with the paper's Table~I filters
($h=\{\frac18,\frac38,\frac38,\frac18\}$ and a two-tap derivative $g$). The edges at scale $2^l$ px
are \texttt{extrema2}'s gradient-modulus maxima: the gradient direction snapped to the row or column
axis, a neighbour whose gradient points the opposite way counted lower, and a gap-filling pass at
the finest scale; they are linked into per-scale H-lines (\texttt{line\_id}). Stored moduli carry
LastWave's normalization (factors close to $1/\lambda_l$). \texttt{Border} \emph{mirror} runs the
whole algorithm on the field mirrored to twice its size, for rasters whose edges do not wrap;
\emph{periodic} is LastWave's own mode. Two defects of the C are corrected: non-square fields and a
single level ($J=1$). \texttt{Algorithm} \emph{printed} selects the paper's printed algorithm as the
research port implements it (Fourier-domain filters on the mirrored torus), kept for comparison.
Fields with nodata pixels are refused, and numba is required.

\textbf{Where the edges are drawn.} In the authors' transform a sample at index $j$ describes
position $j-\frac12$, so maxima and the coarse channel from the second level up are drawn half a
pixel west and north of their index. At the finest level the two gradient components sit half a
pixel apart ($W_x$ at $(j-\frac12, i)$, $W_y$ at $(j, i-\frac12)$), as in the authors' convention;
\texttt{Co-locate level 1} averages each onto $(j-\frac12, i-\frac12)$ for detection only, and the
stored values the reconstruction uses are unchanged.

\textbf{Reconstruction from the edges.} The Outputs rows show \emph{coarse} (the coarse channel
$S_{2^J}$ in the data's units), \emph{thumbnail} ($S_{2^J}$ sampled every $2^J$ pixels, each block
centred on its sample), \emph{recon (edges + coarse)}, \emph{recon (edges only)} (with $S=0$) and
\emph{residual} (the data minus the reconstruction). The reconstruction is LastWave's
\texttt{e2recons}: an initial pass, then alternating projections. Each iteration analyses the
current image, restores the stored values at the maxima and spreads each correction between
neighbouring maxima along rows ($W_x$) and columns ($W_y$) as a $\sinh$ interpolation with decay
$e^{-\kappa/2^l}$ per sample (row and column ends pinned to zero, as in the C), optionally clips the
modulus to decrease away from each maximum, and synthesizes with the coarse channel held fixed.
$\kappa=1$ is the paper's constant; LastWave uses $\kappa=2\ln 5.8\approx3.516$, which reconstructs
markedly better when the coarse channel is pinned and slightly worse for edges only.

The reconstruction knobs live in the right panel's \emph{Reconstruction} section, shown when
\dev{mz\_edges} is in the layer's rack. By default (\texttt{Live} off) no reconstruction row
computes on its own: each shows a reconstruction already cached for the current knobs (the recon
row also its cached preview), else the data, and reads ``press Run'' until Run computes the row on
show. \emph{Run} computes the reconstruction either to convergence (the relative change falls under
the tolerance, the iteration cap is reached, or the constraint residual rises three iterations in a
row, which returns the best iterate) or for a fixed count, with progress and Stop. With
\texttt{Live} on, showing the recon row computes a one-iteration preview, Decay $\kappa$, Clip and
Coarse recompute it as they change, and Run continues from it. Each recon row reads its iterations, why the run stopped and
its SNR against the data (mean removed; for edges only, against the data minus the synthesised
coarse part). ROI results do not reconstruct yet (their rows say so), and the thumbnail shows in the
2-D view. Under \emph{printed} the reconstruction is the research port's alternating projections
with its own \texttt{Mode}, run for the iteration count when a row is shown.

\paragraph{Reconstructing from selected maxima (LastWave).} The rack's filters reach the
reconstruction: at every level the engine runs the chain's filters that apply on that level
alone, and the Reconstruction section's level table
decides what each level contributes. \emph{all}: every maximum; \emph{own} (the default): the maxima
the filters keep there; \emph{near} $s$: the level's own maxima within \texttt{near\_radius} px of a
maximum kept at level $s$ (with the $\alpha$ check, only those whose modulus fits the source chain's
decay $2^{\alpha(l-s)}$ within the tolerance, in $\log_2$); \emph{coder} $s$: the kept positions of
level $s$ carrying this level's own transform values (Mallat \& Zhong's coding mode, \S IX);
\emph{predict} $s$: the kept positions and arguments of $s$ with the modulus $M_s\,2^{\alpha(l-s)}$;
\emph{open}: no constraints, so the alternating projections fill the level from the others. The
\emph{\S IX preset} selects at level 2 and codes levels 1 and 3 from it (the paper codes with $J=3$).
A source must have a selection of its own (\emph{all}, \emph{own} or \emph{near}). With Per-level
filters on, the filter knobs edit the level the Transport shows and each level keeps its own
settings (turning it on starts every level from the current ones). The canvas draws, at the level
on show, the maxima the reconstruction reads there, and the section reads how many of the level's
maxima those are. $\alpha$ comes from the analysis: each maximum propagates up the levels to the
nearest maximum of the same sign within $2^{l-1}$ px, $\alpha$ is the slope of $\log_2$ of the
stored modulus over the linked levels from 2 up (the coarsest level takes the $\alpha$ of the chains
reaching it), and a line takes the median of its points'. From level 2 up the stored modulus
follows $2^{l\alpha}$ (a step 0, a line $-1$, a point $-2$); level 1's staggered two-tap gradient
departs from it by a factor that depends on the full direction of the edge's normal (0.86 to 1.37 on
straight binary steps), so a prediction at level 1 carries that factor. In mirror mode a selection
is applied as removals to all four images of the mirrored field. Every reconstruction row is keyed
on the filters and the table, so each selection caches on its own.

\textbf{Fractional B-spline.} \texttt{Wavelet} \emph{frac\_bspline} replaces the quadratic spline by
Unser \& Blu's symmetric fractional B-spline of order $\alpha\ge1$ as the smoothing function, the
wavelet staying its derivative (one vanishing moment, maxima are edges). Its refinement filter is an
infinite impulse response --- the fractional order has no compact support --- so the analysis runs the
Fourier engine on the mirrored torus whatever \texttt{Algorithm} says, and its reconstruction is the
fractional bank's closed-form synthesis pair, never LastWave's FIR \texttt{e2recons}; the live
preview refuses fractional bundles with a pointed message. The wavelet scale bar draws $\psi_\alpha$ at
the level on show from the exact series, and $\lambda^*$ from the fractional cascade's own level
response (its continuum constant solves $\tan(\omega/4)=(\alpha+1)\,\omega/4\alpha$; $\alpha=3$ gives
the quadratic spline's 1.8595).

\begin{figure}[h]
\centering\includegraphics[width=\textwidth]{frac_bspline.pdf}
\caption{\dev{mz\_edges}, \texttt{frac\_bspline}: the smoothing function
$\theta_\alpha(x)=2\beta_*^\alpha(2x)$, the \emph{symmetric} fractional B-spline of degree
$\alpha$ (Unser \& Blu 1999, eqs.~10--11; $\hat\beta_*^\alpha(\omega)=|\sin(\omega/2)/(\omega/2)|^{\alpha+1}$),
and the wavelet $\psi_\alpha=\theta_\alpha'$ as $\alpha$ varies --- the analytic limit the filter
cascade is pinned to (its maxima sit exactly where the classical $\alpha=3$ path puts them:
no causal phase). $\alpha$ is $\theta$'s H\"older degree; its approximation order is
$\alpha+1$. $\alpha=1$: a triangle and a box pair; $\alpha=3$: the paper's quadratic-spline
wavelet. Only odd integer $\alpha$ gives a compactly supported classical B-spline; other
orders decay algebraically, with small sign-changing tails at the knot spacing (the lobes near
$x\approx\pm1$ on the $\alpha\approx1.5$--$2.5$ wavelets are these, not ringing), and as
$\alpha\to0$ the symmetric spline is \emph{not} a box but develops logarithmic peaks and
oscillating tails (Unser \& Blu, fig.~2). Drawn from the exact time-domain series (their
eq.~11), never by inverting the Fourier transform, so the $\alpha=1$ jumps carry no Gibbs
ringing. This is Mallat--Zhong's dyadic \emph{derivative} wavelet built on a fractional spline ---
exactly one vanishing moment ($\hat\psi\sim i\omega$ at low frequency), since maxima-are-edges is the
method --- not one of Unser \& Blu's fractional spline wavelet bases, which behave like
fractional differentiators $|\omega|^{\alpha+1}$.}
\end{figure}

\subsection{\tool{Wavelet skeleton}{wavelet\_skeleton} --- medial-axis (modulus-minima) extractor}
Tang--You 2003 (the constructed compact-support wavelet $\kappa$: support radius $=$
scale, maxima-pair separation $=$ scale, width- and gray-invariant) $+$ You et al.\ 2006
(modulus \emph{minima} sit on the medial axis, scale-independently). A detector, not
statistics: directional minima gated by a flanking ridge \emph{pair} (each side within
reach $\sim s$ must clear \texttt{edge\_frac} of the peak modulus), valley contrast
(\texttt{t\_frac} of the flanking ridge --- the paper's threshold $T$ made local), and

someone else's slope). Border and nodata neighborhoods (one kernel support) are
distrusted. On \texttt{input=gradient} the detector runs over $\lVert\nabla s\rVert$,
where a diffused scarp (an \emph{edge} in the signal) becomes a ribbon whose axis is the
fault trace. Output is single-scale extrema (H-lines via \texttt{line\_id}).

\subsection{\tool{CDF edges}{cdf\_edges} --- complex cross-diffusion edges}
One complex cross-diffusion evolution (Gilboa small-$\theta$; Barbeiro 2023 for the
scale-space reading), snapshotted at the dyadic schedule
$n=\sigma^2/(2\cos\theta)/\mathrm{d}t$: the Re channel evolves as the Gaussian-smoothed
image and $\operatorname{Im}/\theta \approx t\cdot\mathrm{LoG}$ (machine-pinned), so one
evolution \emph{is} a Mexican-hat scale space. The nonlinear variant modulates diffusivity
by the Im channel (Perona--Malik-style edge stopping through $k$). Final Re (\texttt{filtered})
and Im (\texttt{edge\_channel}) rasters ride the result. Scales are effective Gaussian
$\sigma$ in px.

\textbf{Edge readouts} (\emph{Edges}, \texttt{edge\_mode}), each read from every snapshot:
\begin{itemize}\itemsep2pt
  \item \textbf{Canny (Re)}, stored as \texttt{mz}: the gradient-modulus maxima of the Re
        channel. The gradient is the central difference; its direction is snapped to the
        nearest of the eight neighbour directions, and a pixel is kept where its modulus is
        at least that of both neighbours along it (neighbours wrap at the field's edges).
        This is Canny's non-maximum suppression with a single floor,
        $|\nabla\mathrm{Re}|>\texttt{floor}\cdot\max|\nabla\mathrm{Re}|$, and no hysteresis:
        one threshold and no edge tracking. The Re channel is already the Gaussian-smoothed
        image, so the smoothing is the diffusion's own. The same reading is the Mallat--Zhong
        edge definition, which makes \dev{cdf\_edges} directly comparable to \dev{mz\_edges}
        at matched scales; applying it to the diffusion is this app's own graft.
  \item \textbf{Marr (Im)}, stored as \texttt{marr}: the zero crossings of the Im channel
        ($\approx t\cdot\mathrm{LoG}$, the Marr--Hildreth edges), where a pixel and the next
        one along its row or column differ in sign, kept where the slope of Im exceeds
        \texttt{floor} times its maximum. This is the CDF authors' own edge concept:
        Barbeiro's $v$ ``in the role of edge detector''.
\end{itemize}
Under the \texttt{follow} detector both readouts give way to xsmurf's contour following on the
Re channel, and \texttt{edge\_mode} and \texttt{interpolate} are inert.

\subsection{\tool{Tucker (HOOI / HOSVD)}{tucker\_HOOI\_HOSVD} --- delay-embedded Tucker decomposition (Tucker-SSA)}
A Tucker decomposition of a delay embedding of the field --- Broomhead--King singular-spectrum
analysis carried to 2-D and multiband data by a Tucker decomposition instead of one SVD. (It was
first named \dev{tucker\_havok}; HAVOK's regression on the delay coordinates was never part of
it.) Nothing is ever materialized: bases come from Grams of contiguous window slabs, and the
reconstruction averages each pixel over the windows covering it.

\begin{itemize}\itemsep2pt
  \item \textbf{Embedding.} \texttt{delay\_2d} (default): \emph{both} axes delayed ---
        every $L\times L$ patch ($L=$ Delays), tensor (delay$_y$, delay$_x$, $y'$, $x'$
        [, band]), so no image axis plays ``time''.
        \texttt{delay}: a 1-D Hankel embedding along one axis (Tape axis) --- for data where
        one axis really is time (e.g.\ a reconstructed tape); on an ordinary 2-D field it
        biases the result toward that axis. \texttt{none}: the array's own modes (rows,
        columns[, band]).
  \item \textbf{Method} --- a two-state button. \textbf{HOSVD}: one pass, each mode's leading
        singular vectors. \textbf{HOOI}: that HOSVD refined by \emph{HOOI sweeps} alternating
        passes, each mode re-derived with the others fixed (monotone in the kept core
        energy; the fast path equals a materialized HOOI to $10^{-8}$).
  \item \textbf{Components} (at most 32, largest core-energy share first): under
        \texttt{delay\_2d} one per kept (vertical, horizontal) delay-pattern pair $(a,b)$;
        \emph{Orientation} \texttt{combined} adds each pair to its twin $(b,a)$
        ($r(r+1)/2$ components for delay rank $r$). Tape: one per delay pattern; none: one per
        rows-mode vector. They sum to the reconstruction.
  \item Separable by construction: a pattern is a vertical pattern $\otimes$ a horizontal one,
        so an oblique structure spreads over several pairs. \dev{ssa2d} is the
        rotation-invariant alternative.
\end{itemize}

\subsection{\tool{2-D SSA}{ssa2d} --- 2D singular-spectrum analysis}
Golyandina \& Usevich (2010). Every $L_r\times L_c$ window of the image is one column of the
Hankel-block-Hankel matrix $\mathbf W$ ($L_rL_c\times K_rK_c$, $K=N-L+1$); \emph{one} SVD
$\mathbf W=\sum_i\sqrt{\lambda_i}\,U_iV_i^{\mathsf T}$ gives the eigentriples. Reshaped, $U_i$
is an \textbf{eigenarray} --- an $L_r\times L_c$ pattern of any shape, not restricted to
separable products, which makes 2D-SSA invariant to rotations of the image axes --- and $V_i$ a
\textbf{factor array} ($K_r\times K_c$). Each rank-1 term, averaged back onto the image (every
pixel over the windows covering it), is an \textbf{elementary component}; all of them sum to
the image. Ranks (the paper's \S4, pinned by tests): an oblique cosine
$\cos 2\pi(\omega_xk+\omega_yl)$ is rank 2, a product of cosines rank 4, a sum of $m$ 2-D
exponentials rank $m$.

\textbf{Solvers.} None forms $\mathbf W$.
\begin{itemize}\itemsep2pt
  \item \emph{Lanczos} (the default), \emph{PROPACK} and \emph{randomized} use FFT products: $\mathbf
        W^{\mathsf T}u$ and $\mathbf Wv$ are 2-D correlations of the image, done at its own size,
        whose kept parts never wrap (Korobeynikov 2010; Golyandina et al.\ 2015). They find only
        the $k$ leading eigentriples --- ARPACK's Lanczos on the implicit $\mathbf W\mathbf
        W^{\mathsf T}$; PROPACK's bidiagonalization of $\mathbf W$, with full reorthogonalization
        (its default partial one returns ghost copies of the leading triplet when the 32-bit FFT
        products are adjoint only to $\sim10^{-7}$); or a randomized range finder whose power
        iterations are re-orthonormalized after every product (Halko et al.\ 2011; Lopes et al.\
        2024). Components are FFT convolutions of eigenarray and factor array. They agree with the
        dense route to float32 tolerance. Measured on a $2048^2$ field with a $64\times64$ window
        and $k=16$: Lanczos 6\,s, randomized 25\,s, PROPACK 42\,s.
  \item \emph{Dense}: the lag covariance $\mathbf W\mathbf W^{\mathsf T}$ ($(L_rL_c)^2$)
        accumulated from blocks of window rows, its full eigenbasis, then $\mathbf W^{\mathsf
        T}U$ in the same blocks; float64 BLAS, equal to an explicit SVD of $\mathbf W$ to
        $10^{-9}$. Limited to windows of 1600 entries ($40\times40$, about 4\,s on a $256^2$ field).
        An FFT solver hands over to it when the kept count reaches the window size.
\end{itemize}
The shares $\lambda_i/\operatorname{tr}(\mathbf W\mathbf W^{\mathsf T})$ are exact on every route
(the trace is the sum of the squared pixels weighted by their window counts). Each eigenarray is
signed so that its largest entry is positive. Large outputs are stored at the app's precision.
Single-band fields only. NaN pixels are filled with the finite mean for the decomposition and
re-masked in every output. Also returned: the \textbf{w-correlation} matrix (the paper's
Def.~3.18) of the kept components --- the grouping aid shown in the Components window.

\textbf{Keeping and grouping} (Lopes et al.\ 2024). \emph{Keep: energy} treats
\texttt{n\_components} as the most to find and keeps the fewest whose cumulative share reaches
the threshold (the row note says when it was not reached). This 2D-SSA is uncentred, so on a raw
field the first eigentriple, the mean, often carries most of the energy on its own.
\emph{Show: cluster} shows one group of an automatic grouping: average-linkage clustering on
$1-|\text{w-correlation}|$, cut at the cluster distance, clusters ordered by share. The cluster knobs
are view settings, so changing them never re-decomposes.

\textbf{Edges.} A pixel near the edge of the analysed region is covered by fewer windows. On a
region of interest the tool reads a margin of real data around it (\texttt{margin\_windows}
windows of $\max(L_r,L_c)-1$ pixels; at one window every ROI pixel is fully covered) and crops
back. On the whole field there is no data beyond the edge. Lopes et al.'s mirror extension is
available (\emph{Whole-field edges: mirror}), but off by default: in 2-D a reflected wave is a
different wave (an oblique wave flips a frequency component), so the extension adds rank. On two
test waves it raised the edge error 3--18$\times$, where the real-data margin of an ROI lowered
it by about 10\%.

\section{Inpainting and fusion}\label{sec:inpaint}

the cascade (the Histograms window).

\section{Microcanonical MFA}\label{sec:micro}
Per-pixel singularity exponents $h(x)$ from the model
$T(x,r)\approx\alpha(x)\,r^{h(x)}$ (Turiel 2008), $D(h)$ by direct histogram --- the
formalism that is \emph{not} canonical/Legendre. One tool per functional; both expose the
Pont 2006 estimator pair: \textbf{regression} (per-pixel log--log slope over the scale
grid; the prefactor cancels exactly; resolves both limbs of $D(h)$) and
\textbf{punctual} (the finest scale alone, ensemble-mean normalized; sharpest
localization, the most-singular-set extractor; cannot resolve the right limb; carries an
$\alpha(x)/\langle\alpha\rangle$ bias). Both estimators share the same cross-scale
no-support mask --- they agree on \emph{where} an exponent exists and differ in
\emph{how}. Under punctual, $\kappa$/\texttt{n\_scales} shape only the mask and
\texttt{r2\_map} is honestly all-NaN.

\subsection{\tool{Microcanonical MFA, measure}{holder\_measure} --- gradient-measure route}
$T$ = positive unit-mass kernel over $\lVert\nabla s\rVert$ (finite differences first,
then $g_0$-class smoothing). For measure-like / edge-sparse fields; slope $=h$.
The scale knob $r_1$ is the kernel's \emph{dilation scale} (for the Gaussian: its
standard deviation) --- positive kernels have no zero crossings, and their resolution
floor is the pixel, except for the compactly supported q-Gaussian (below). Kernel trade-off (Turiel App.~A): Gaussian resolves every $h$;
Lorentzian truncates at $h<2\beta-d$ but localizes sharpest; q-Gaussian interpolates;
\texttt{frac\_gaussian} fractionalizes the envelope, $e^{-\rho^{n}/2}$ ($n{=}2$ is the
Gaussian exactly).

The q-Gaussian is Tsallis's $e_q^{-\rho^2/2r^2}$ with
$e_q^{x}=[1+(1-q)x]_+^{1/(1-q)}$ (Borges et al.\ 2004, eq.~9), for
$-1\le q\le 3$. Above $q=1$ it has power-law tails (Student-t / Lorentzian:
$q\equiv 1+1/\beta$ with $\rho^2/r^2$ rescaled); $q=1$ is the Gaussian; below $q=1$ it is
\emph{compactly supported}, radius $r\sqrt{2/(1-q)}$ --- $q=0$ is the Epanechnikov
paraboloid, $q=-1$ a half-dome of radius $r$, and $q\to-\infty$ the Dirac $\delta$. For
$q\ge2$ the 2-D kernel has no finite mass (the Lorentzian $\beta\le1$ case), so the result
depends on the field size; the $q$ knob shows a warning there. The compact kernel (below $q=1$)
is the steepest decrease there is, so it carries a resolution floor: the $r_1$ knob warns when
its support disc, of radius $r/\sqrt{\beta(1-q)}$ for width $\beta$, is less than 2\,px across,
i.e.\ below $r_1=\sqrt{\beta(1-q)}$ (at most 1\,px at the default width).

\subsection{\tool{Microcanonical MFA, multiaffine}{holder\_multiaffine} --- wavelet-projection route}
$T=|\psi_r * s|$ with a zero-mean wavelet applied to the \emph{raw signal} (derivative
order lives inside the kernel). For smooth / function-class fields (DEMs); slope
$=\gamma$, with $h_{\text{measure}}=\gamma-1$. Here $r_1$ is the \emph{zero-crossing
radius}: every wavelet in the menu is calibrated to change sign at radius $r$, so for a
wavelet with one crossing the fig.-2 minimum-resolution rule reads $r_1\ge 1$ (more crossings,
or a compact support, raise it: \emph{Resolution floor} below). The g-ladder is the
vanishing-moment axis (order $n$ measures only $\gamma<n$): \texttt{g1}/\texttt{g3} are
the fractional family at $n{=}1,3$; \texttt{g2} \emph{is} the Ricker;
\texttt{lorentzian\_marr} is the Laplacian (Marr operator) of the Lorentzian envelope (true
tail $\rho^{-2\beta-2}$, truncation $\gamma\ge 2\beta$); \texttt{frac\_gaussian} makes the
order a real knob ($\psi\propto{}_1F_1(\frac{n+2}{2};1;-\rho^2/2\sigma^2)$, $n{=}2$
reproduces the Ricker exactly): $n$ is a fractional \emph{differentiation} order
($\hat\psi\sim|k|^n$ at low frequency), so exact moments vanish only for the integer orders
below $n$ --- a fractional $n$ is not ``$n$ vanishing moments'' --- and $\gamma<n$ is measurable.

\texttt{q\_mexican} is the q-Mexican hat of Borges et al.\ (2004, eq.~15): the second
derivative of the q-Gaussian \emph{raised to the power $2-q$}. In 2-D (the Laplacian) this
gives
\[
  \psi_q(\rho)\;\propto\;\bigl[1-(2-q)\,b\rho^2\bigr]\,\bigl[e_q^{-b\rho^2}\bigr]^{q},
  \qquad b=\frac{1}{(2-q)\,r^2},
\]
so the zero crossing sits at $\rho=r$ for every $q$, and $q=1$ is the Ricker exactly. The
paper's $q<3$ is the 1-D bound: in 2-D the Laplacian of $[e_q]^{2-q}$ vanishes identically
at $q=2$ and never changes sign above it, so the knob runs $-1\le q\le1.95$. For $q\ge0$
the wavelet is bounded; for $q<0$ it diverges at its cutoff (still integrable) and the knob
shows a warning. Because $[e_q]^{2-q}$ is itself a $q'$-Gaussian with $q'=1/(2-q)$, this is
the family of Laplacians of q-Gaussians under a relabelled index: \texttt{q\_mexican} at $q$
equals \texttt{lorentzian\_marr} at $\beta=(2-q)/(q-1)$ for $1<q<2$ (e.g.\ $q=1.5\equiv\beta=1$),
with tail $\rho^{-2/(q-1)}$ and truncation $\gamma\ge2(2-q)/(q-1)$.

\textbf{The q width $\beta$} (both q-kernels) is the $\beta$ of $e_q^{-\beta x^2}$, a toggle away
from the paper's two choices.
\begin{itemize}\itemsep2pt
  \item \textbf{Fixed} (default $\beta=\tfrac12$): the unit-variance Gaussian per component at
        $q=1$, in any dimension. The scale $r$ keeps its meaning at $q=1$: $\sigma=r$ for the
        q-Gaussian, the zero crossing at $r$ for the q-Mexican hat. At other $q$ the q-Mexican
        hat's zero crossing drifts to $r/\sqrt{2\beta(2-q)}$.
  \item \textbf{q-paired}: Borges et al.'s $\beta=1/(3-q)$ holds the q-Gaussian's
        \emph{escort} (q-)variance $\int x^2[e_q]^q/\int[e_q]^q$ at one. In $d$ dimensions that
        variance is $1/(\beta(d+2-dq))$ per component, so the pairing is $\beta=1/(d+2-dq)$:
        $1/(3-q)$ in 1-D and $\beta(q)=1/(2(2-q))$ here.
  \item The q-Mexican hat's zero crossing sits exactly at that escort RMS radius, so the
        pairing also pins it (at $r$, for every $q$: the tool's classic calibration). The two
        settings agree at $q=1$.
  \item The pairing exists exactly where the 2-D q-Mexican hat is admissible, $q<2$: the
        escort variance and the zero mean both need $d+2-dq>0$. A q-paired q-Gaussian
        therefore refuses $q\ge2$.
  \item In real space the normalisation is done numerically at every scale, so the paper's
        closed-form constants are not used. (In 2-D they happen to be elementary:
        $A_q=\sqrt{\beta(3-q)(1+q)/\pi}$ for the q-Mexican hat,
        $B_q=\sqrt{\beta(3-q)/\pi}$ for the modulated q-Gaussian. The flat Jacobian
        $\rho\,d\rho=du/2\beta$ turns every integral into a Beta function with integer
        arguments, where 1-D keeps $\Gamma(\tfrac12)$-type ratios.)
\end{itemize}

\textbf{Resolution floor on $r_1$.} A discretized wavelet must separate its positive and
negative parts, so its zero crossings set the minimum attainable resolution, and more crossings
cost resolution (Turiel et al.\ 2008, fig.~2 and \S4.2.1); Turiel (2009) puts a Mexican hat's
inner minimum scale at ``several pixels''. Neither gives a number. The tools read the rule as:
every sign lobe at least 2\,px across at $r_1$, the central disc counted by its diameter. The
edge of a compact support is not a sign change, but it closes the last lobe. The $r_1$ knob
warns below the floor and never refuses.
\begin{itemize}\itemsep2pt
  \item One crossing at $r$ (\texttt{g1}, \texttt{g2}, \texttt{lorentzian\_marr},
        \texttt{frac\_gaussian} for $n\le2$): the floor is $r_1=1$, as before.
  \item More crossings: \texttt{g3} 1.32\,px (its ring is $1.52\,r$ wide); \texttt{frac\_gaussian}
        at $n=4$ and $5$, 1.41 and 1.46\,px.
  \item \texttt{q\_mexican}: its crossing sits at $\rho_0=r/\sqrt{2\beta(2-q)}$ ($r$ when q-paired)
        and, below $q=1$, its support ends at $\rho_0\sqrt{(2-q)/(1-q)}$. The negative ring between
        them narrows as $q$ falls, and below $q\approx0.875$ (q-paired) it is the narrowest lobe:
        floor 2.73\,px at $q=0.5$ and 4.42\,px at $q=0.1$. A fixed width $\beta$ is a pure
        dilation of the wavelet, so it rescales the floor by $\sqrt{2\beta(2-q)}$.
  \item \dev{holder\_measure}: only the compact q-Gaussian has a floor (above).
\end{itemize}

\textbf{Wavelet space: real or Fourier} (both tools). \emph{Real} (the default, Turiel's
construction) samples each kernel on the pixel grid and normalizes it there. \emph{Fourier}
evaluates the same continuous kernel's closed-form 2-D transform at $r\mathbf{k}$: a Mat\'ern
function of $k$ for a q-Gaussian with $q>1$ (and the Lorentzian, $q=1+1/\beta$), a Jahnke--Emde
function for $q<1$, $k^n e^{-k^2/4u_0}$ for the fractional family, evaluated stably at every
$q$. The kernel is then band-limited rather than sampled.
\begin{itemize}\itemsep2pt
  \item Measure route: unit mass exactly. Multiaffine route: zero mean exactly, and the kernel
        is the $L^1$-dilated continuous wavelet, so $T$ equals the real construction's times the
        mother wavelet's $L^1$ norm (a constant that cancels in every slope) wherever both are
        exact.
  \item They differ where sampling matters: at the smallest scales, for compact kernels (the
        Fourier one rings slightly), and for heavy tails, which real space cuts at the edge of the
        padded grid (about $10^{-4}$ at the default padding for a $\rho^{-6.7}$ tail).
  \item Fourier is refused on the measure route for \texttt{frac\_gaussian} (no closed-form
        transform), and for a q-Gaussian at $q\ge2$ or a Lorentzian with $\beta\le1$ (no finite
        mass to normalize by).
\end{itemize}

\subsection{Band reconstruction: the \texttt{band} and \texttt{band\_mask} outputs}\label{sec:band}
Both Microcanonical MFA tools reconstruct the field from a singularity band. The band
$h\in[h_{\text{lo}},h_{\text{hi}})$ of the cached $h$ map, cleared of islands outside the size
range, is the mask; the reconstruction is the gradient-restricted Fourier inversion of the
analysed values on that mask (Turiel eq.~65, symmetric-extension border fix). Two output rows
carry them, \emph{band reconstruction} (\texttt{band}) and \emph{band mask}
(\texttt{band\_mask}), and \texttt{Show} picks what the canvas draws: the $h$ map, the band or
its mask. The band row reads its PSNR against the data and the share of pixels in the band, the
mask row the share.

The band knobs are view-only and sit in the right panel's \emph{Reconstruction} section. Only
the two outputs read them: scrubbing the band recomputes the reconstruction from the cached $h$
map, and the analysis key leaves them out. A saved project gains them at their defaults.
Sweeping the band and watching the reconstruction is the workflow. \emph{Reconstruct\ldots}
(the Band dialog) previews the band live; on a whole-field layer headed by a Microcanonical MFA
tool, a band row of a stack included, it writes the band into that step's knobs and shows the
band row. On an ROI layer, and on a layer headed by \dev{holder\_map}, it adds a
\dev{band\_recon\_measure} or \dev{band\_recon\_multiaffine} child, which runs the same $h(x)$
engine with the band as keyed knobs and shows the reconstruction as its raster.

\section{Planned: q-generalized wavelets}\label{sec:todo}
Not implemented yet --- recorded here so the design stays in one place. Borges et al.\
(2004) generalize the Mexican hat (above), the Morlet wavelet (a q-Gaussian-modulated
plane wave, their eq.~23) and the trigonometric functions (an even/odd pair of
q-trigonometric wavelets, their \S4), and note that ``other wavelets, as well as scaling
functions, may be generalized along the lines here introduced, for instance, the Meyer
wavelet or the sinc function.''
\begin{itemize}\itemsep2pt
  \item \textbf{q-generalized \texttt{g1} and \texttt{g3} for \dev{wtmm2d}.} WTMM's
        analyzing wavelets must stay \emph{derivatives of a smoothing function}
        ($\psi=\partial\theta$), so that maxima mark edges. The filters are built in the Fourier
        domain, so they need the \emph{2-D} transform of the q-Gaussian, a Hankel transform with
        Bessel order $1/(q-1)-d/2$, one half lower than the paper's 1-D order. That transform is
        now built and evaluated stably at every $q$ (the Mat\'ern and Jahnke--Emde functions used
        by \emph{Wavelet space: Fourier}, \S\ref{sec:micro}).
        \begin{itemize}\itemsep1pt
          \item q-\texttt{g1}: $\partial\theta_q$ with $\theta_q$ the unit-mass q-Gaussian, so the
                $L^1$ normalization is unchanged ($\hat\theta_q(0)=1$); it exists for $q<2$.
          \item q-\texttt{g3}: the power-$(2-q)$ recipe makes the Laplacian's envelope a
                $q'$-Gaussian with $q'=1/(2-q)$, whose mass is finite only for $q<3/2$. For
                $3/2\le q<2$ the wavelet is still finite ($k^2$ cancels the divergence at
                $k=0$), but $\hat\theta(0)=1$ can no longer fix its scale, so it needs another
                normalization there, such as unit $L^1$ norm.
        \end{itemize}
  \item \textbf{q-Morlet} and the \textbf{q-trigonometric} pair (oriented/directional
        analysis).
  \item \textbf{q-Meyer} and \textbf{q-sinc}, as the paper suggests.
\end{itemize}

\section*{Appendix: result contracts}
\begin{itemize}\itemsep2pt
  \item The named data contracts with the result keys each covers, and what each tool
        consumes and produces, are tabled in \S\ref{sec:contracts}.
  \item \textbf{Extrema schema} (all edge/skeleton analyzers): per-scale
        \texttt{\{x, y, mod, arg, line\_id\}}; \texttt{line\_id} groups H-lines,
        $-1$ marks isolated points. \texttt{scales} is the matching scale array (px).
  \item \textbf{h-map contract} (holder tools): \texttt{h\_map} displays in place of the
        field through the ordinary raster path; \texttt{r2\_map} rides along
        (all-NaN under punctual). The \texttt{band} and \texttt{band\_mask} outputs are
        lazy rasters with keys of their own (\S\ref{sec:band}). \texttt{raster\_out}
        (\dev{band\_recon\_measure}, \dev{band\_recon\_multiaffine}) displays the
        reconstruction; \texttt{h\_map}/\texttt{band\_mask} ride for the dialogs.
  \item \textbf{cdf extras}: \texttt{filtered} (final Re) and \texttt{edge\_channel}
        (final Im) rasters.
  \item The vector (3-D) view draws one extrema layer: the level the layer shows
        (\S\ref{sec:transport}).
  \item \sloppy\textbf{Decomposition extras}: \dev{ssa2d} --- \texttt{ssa\_recon},
        \texttt{ssa\_residual}, \texttt{ssa\_components} $(n,n_y,n_x)$,
        \texttt{ssa\_eigen\_share}, \texttt{ssa\_eigenarrays} $(n,L_r,L_c)$,
        \texttt{ssa\_factor\_arrays} $(n,K_r,K_c)$, \texttt{ssa\_w\_correlation} $(n,n)$.
        \dev{tucker\_HOOI\_HOSVD} --- \texttt{tucker\_recon}, \texttt{tucker\_residual},
        \texttt{tucker\_components} / \texttt{tucker\_combined\_components} with their
        energies, core, factors, energy per mode; on a multiband field also
        \texttt{tucker\_recon\_bands} / \texttt{tucker\_residual\_bands} $(n_y,n_x,n_c)$ (the
        display shows band 1). A view step writes \texttt{raster\_out} and, for a named view,
        \texttt{\_view\_note} (what the layer row appends).
  \item \textbf{Inpainting extras}: \dev{inpaint} --- \texttt{fill\_mask} (region ids),
        \texttt{\_estimate} (the estimate before the final step, float32),
        \texttt{\_heldout\_mask}, \texttt{\_hists} (the per-level $\ln|\eta|$ and $\ln|c|$
        histograms), \texttt{\_abacus}, \texttt{\_warnings}, \texttt{\_filled\_fraction};
        \dev{dwt2d} --- \texttt{scales} ($2^j$ px), \texttt{\_dwt\_levels}. A \dev{fill} clone's
        provenance carries \texttt{fill}; an analyzer result after it carries \texttt{\_fill}.
  \item \textbf{Derivative file}: the RasterField npz keys (\texttt{schema}, \texttt{name},
        \texttt{values}, \texttt{x\_axis}, \texttt{y\_axis}, \texttt{units},
        \texttt{frame\_meta}, \texttt{provenance}) plus, when it carries vectors,
        \texttt{vec\_e\_*} (extrema, CSR-packed), \texttt{vec\_c\_*} (maxima lines) and
        \texttt{vec\_scales}. A vector-only derivative's raster is all-NaN on the same grid.
\end{itemize}
